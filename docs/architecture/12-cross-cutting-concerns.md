## 1. Error handling and diagnostics

| Layer | Mechanism |
|---|---|
| Library crates | `thiserror` enums per crate (`SpecError`, `DataError`, `CompileError`, `RenderError`, `AudioError`, …). No panics in library code; `unwrap`/`expect` are denied by lint outside tests |
| User-facing | `Diagnostic` ([05 §7](05-compiler-and-score-ir.md#7-diagnostics)) with stable codes `SNR-<AREA>-<NNN>` and rule IDs, rendered by `miette` (CLI) or the diagnostics panel (desktop) |
| Apps | `anyhow` only at app boundaries (CLI `main`, xtask); everything else is typed |
| IPC | Typed error payloads (`code`, `message`, `hint`, `pointer`) generated to TypeScript |
| Audio thread | Panic-free by construction; callback wrapper fails to silence ([06 §11](06-audio-engine.md#11-failure-handling)) |

**Error code registry.** Codes are listed in `docs/reference/error-codes.md` (generated by `cargo xtask codes` from A03). A code, once published, is never reused for a different meaning.

**Message style.** State the cause and the fix, with units, in one or two sentences. No exclamation marks, no blame. Example: `SNR-SPEC-031: pitch range [1400, 400] Hz is reversed. Use "polarity": "negative" to invert the mapping instead.`

## 2. Logging, tracing and observability

- `tracing` with structured fields, never called from the audio thread.
- **Local only.** Rotating log files in the OS log directory, 7 days or 50 MB. `RUST_LOG`-style filtering through settings.
- **No personal data** in logs. File paths are logged as basename plus a hash. Data values are never logged at `info` or above.
- **Diagnostics overlay** (desktop, toggleable): audio callback load, xrun count, buffer size and latency, IPC queue depth, last compile time. Screen-reader-accessible as a table.
- **Bug-report bundle:** a user-initiated export of logs, settings (redacted), the environment and the last diagnostics as a zip the user can inspect before sharing. Nothing is uploaded automatically.

## 3. Configuration and settings

**Precedence (lowest → highest):** built-in defaults → user settings → active profile → project → spec → command-line flags or an explicit UI action.

| Store | Contents | Format |
|---|---|---|
| Settings | Device, buffer size, theme, keymap overrides, modalities, update channel, consent flags | JSON + schema, versioned with migrations |
| Profiles | Perceptual and interaction preferences (SDR-38) | Portable JSON |
| Project | Specs, data snapshots, per-project overrides | `.sonarithm` bundle (§4) |

Every effective value is inspectable through `sonarithm inspect --settings` and the desktop "Effective settings" view, and is announced on request.

**As built (B03-T08, [ADR-0020](../decisions/0020-profile-format-v1.md)).** The app core's `settings_effective` gives every setting with its layer. Profiles live in `profiles/` in the app-config folder and `settings.json` names the active one; the project layer is the bundle's `profiles/project-profile.json`. The CLI's `inspect --settings` follows when the CLI uses the app core (A07).

## 4. Project file format

`.sonarithm` is a **ZIP container** (stored, not compressed, for large Parquet members; deflate for JSON):

```text
project.sonarithm
├── manifest.json            # format version, generator version, specs, datasets, member list with sha256 (no timestamps)
├── specs/
│   └── <spec-id>.json       # one or more specs
├── data/
│   └── <dataset-id>.parquet # snapshots with snr.* metadata and provenance columns
├── profiles/
│   └── project-profile.json # optional per-project overrides
├── annotations/
│   └── <dataset-id>.json    # user notes, corrections log (PLOTSONA user_edited history)
└── renders/
    └── <name>.render.json   # manifests of renders made from this project (audio files stay external)
```

- The **format version** is independent of the app version. Readers refuse newer major versions and migrate older ones explicitly.
- Data can be **embedded** (a snapshot, the default for reproducibility) or **linked** (a path plus fingerprint; a missing or changed fingerprint is a warning on open).
- Projects never store secrets (API keys) or absolute user paths.
- Version 1 of the format is fixed by [RFC-0002](../rfcs/0002-project-format-v1.md) ([ADR-0018](../decisions/0018-project-format-v1.md)).

## 5. Internationalization and localization

| Area | Approach |
|---|---|
| Message catalogues | Fluent. The `.ftl` files live in `crates/sonarithm-i18n/locales/<locale>/` and are embedded in the crate (`fluent-bundle`); `@sonarithm/i18n` loads the same files in the UI (`@fluent/bundle`), so a message ID means the same text in Rust announcement templates and in the UI. IDs are kebab-case with an area prefix: `unit-`, `common-`, `ui-`, `announce-` (B03). A contract test runs the same cases (`crates/sonarithm-i18n/tests/fixtures/contract.json`) through both and expects identical text (B02-T08) |
| Numbers, dates, units | Numbers through ICU4X with `Intl.NumberFormat`'s digit rules (half-expand rounding from the shortest round-trip digits, at most three fraction digits by default), so Rust and the UI print the same digits (F-130). Dates through ICU4X in the proleptic Gregorian calendar. Each unit message prints a value in one of three forms: the symbol for visual text and braille, and terse and verbose spoken names ("°C", "degrees C", "degrees Celsius"); UCUM codes and symbols map to unit messages, and unknown units are printed as written |
| Locale choice | A language with a catalogue uses it, with the requested locale's formats (`en-GB` reads the English catalogue with British dates); a language without one falls back to English text and English formats, so a sentence never mixes languages |
| Pseudo-locale | `en-XA`: the English catalogue with accented letters, about 40 % extra length, and `⟦ ⟧` around every message. The check accepts only text that is exactly one marked message, so it catches hard-coded strings, concatenation and truncation. It runs on every catalogue message in Rust and TypeScript (B02-T08) and on every composed announcement (B03); the UI's pseudo-locale run for clipping arrives with the Playwright suite (B02-T03) |
| Hard-coded UI text | The ESLint rule `sonarithm/no-literal-ui-string` rejects JSX text and user-facing attribute strings in `.tsx` and `.jsx` files |
| Right-to-left | Layout tokens are logical (`inline-start`); full RTL support is post-1.0 |
| Locales | English (B03), plus one more locale in B07 to prove the pipeline, chosen with the community |

## 6. Security and threat model

| Asset | Threat | Vector | Mitigation |
|---|---|---|---|
| User's machine | Code execution via a malicious file | Crafted CSV, XLSX, SVG, PDF, image, project zip | Memory-safe Rust parsers; `cargo-fuzz` on every importer; size and time budgets; zip-slip protection; no macro or script execution from files |
| User's machine | Malicious plugin | Third-party WASM engine | wasmtime sandbox; no FS or network capabilities; fuel and epoch limits; compile-time only; manifest checksum; signatures (v1.1) |
| User's machine | Malicious stream endpoint | WebSocket or MQTT payloads | Schema validation; bounded buffers; rate limits; connections only on explicit user action |
| User's hearing | Excessive level | Bad spec or bug | Start-up gain ramp; true-peak limiter; level warnings ([06 §10](06-audio-engine.md#10-hearing-safety-and-levels)) |
| User's data privacy | Exfiltration | Telemetry, cloud AI | No telemetry; network-deny test; per-action consent for cloud; keychain for keys |
| Update channel | Malicious update | Compromised release | Signed updates (cannot be disabled); two-custodian keys; build provenance attestations; immutable releases |
| Supply chain | Compromised dependency | crates.io, npm, actions | cargo-deny (advisories, bans, sources), lockfiles, SHA-pinned actions, Dependabot or Renovate, Scorecard |
| IPC surface | UI-originated misuse | Compromised webview content | CSP without remote content; capability-scoped commands; Rust-side input validation |

The full process for reporting and handling vulnerabilities is in [SECURITY.md](../../SECURITY.md).

## 7. Privacy

- **No telemetry by default** and no analytics SDKs. If usage statistics are ever added, they follow the Go model: collected locally, uploaded only on explicit opt-in, documented field by field ([ADR-0012](../decisions/0012-privacy-and-telemetry.md)).
- **Update checks** are a documented, single, anonymous request, and can be disabled. The first run asks for consent.
- **Crash reports** are local. Upload is opt-in per report, showing the contents first.
- **Research studies** use separate, explicit consent flows and their own data-management plans ([research-paper/evaluation-plan.md](../research-paper/evaluation-plan.md)).

## 8. Performance budgets

**Reference hardware** (re-validated at the A02 gate):

| Platform | Reference machine |
|---|---|
| Windows | 4-core x86-64 laptop CPU (2021 or newer), 16 GB RAM, integrated GPU, WASAPI shared mode, built-in or USB audio |
| macOS | Apple M1, 8 GB RAM, built-in audio |
| Linux | The same x86-64 class as Windows, PipeWire, Mesa GPU (and an NVIDIA variant for webview checks) |

**Development machine (owner, 2026-10-18):** Windows 11 laptop, Intel i7-14650HX, NVIDIA RTX 4050 Laptop GPU (6 GB) plus the Intel iGPU, 16 GB RAM. It is much faster than the Windows reference machine, so a budget measured on it passes only with headroom: a result above 50% of a budget is re-measured on reference-class hardware, or with the CPU limited, before the budget is declared met. Linux checks run from an Ubuntu live USB or dual boot on this machine, which also covers the NVIDIA WebKitGTK case. macOS checks run on CI runners until a Mac is available (risk R-22).

| ID | Budget | Target | Measured by | From phase |
|---|---|---|---|---|
| PB-01 | Key press → cue onset | ≤ 50 ms p95 (256 frames, 48 kHz) | Loopback harness | A02, B03 |
| PB-02 | Audio robustness | 0 xruns / 10 min at 128 frames | Soak test | A05 |
| PB-03 | Offline render speed | ≥ 50× real time (4 tracks, 10k events) | Criterion | A05 |
| PB-04 | Compile time | ≤ 200 ms (100k rows × 4 tracks); ≤ 1 s (1M rows) | Criterion | A06 |
| PB-05 | CSV ingest | ≤ 1.5 s for 1M rows × 5 columns | Criterion | A04 |
| PB-06 | Determinism | Byte-identical Score; audio null residual ≤ −90 dBFS; ΔLUFS ≤ 0.1 | Golden tests | A05 |
| PB-07 | Cold start | ≤ 2 s to an interactive workspace | Startup bench | B01 |
| PB-08 | UI frame time | 60 fps playhead; ≤ 8 ms script per frame with 1M-point series | Frontend perf test | B04 |
| PB-09 | IPC bulk transfer | ≤ 30 ms for a 1 MB binary view on all OSes | IPC bench | A02, B01 |
| PB-10 | Memory | ≤ 500 MB resident with a 1M-row dataset open | Desktop soak | B05 |
| PB-11 | Streaming | 1 kHz input for 1 h: 0 xruns, bounded memory | Stream soak | B06 |
| PB-12 | Installer size | ≤ 40 MB without ML models | Release CI | C06 |
| PB-13 | Python wheel size | ≤ 15 MB per platform | Release CI | A07 |

Results are recorded in [research-paper/benchmarks-log.md](../research-paper/benchmarks-log.md). A regression of more than 10% against the last release blocks release unless it is explained in the release notes.

## 9. Licensing compliance in the product

- An **About → Licences** view lists every third-party component with its licence, generated at build time from Cargo and npm metadata, and includes the OFL font texts and the Lucide ISC + Feather MIT notices. The bundled fonts' notices come from `@sonarithm/ui/licenses.json`, generated with the fonts (B02-T02).
- Copyleft components (MP3 via LAME) are only present in builds that enable their feature, and then appear in the licences view.
- Model weights (D04) show their licence before download.
