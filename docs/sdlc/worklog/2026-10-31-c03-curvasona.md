## What was done

- **C03-T01:** the `sonarithm-curvasona` crate (not published until the facade uses it, C03-T07). The `expr` facade parses the expression itself and lowers it to a fully parenthesized exmex form; exmex 0.21 evaluates and differentiates it. The `function` source samples the domain into `x`, `y`, `dy`, every row `synthetic`. Codes `SNR-ENG-400` to `406`; fuzz target `expr_parse` (nightly); licence check of exmex and rubato in supply-chain-and-licensing; evalexpr was already banned in `deny.toml`. `sonarithm_data::SourceKind::Function` added.

- **C03-T02:** `scan` finds poles, holes, jumps, undefined spans and off-screen spans from the expression's guards, and the 40-curve suite (`suite`) checks it. Code `SNR-ENG-407`.
- **C03-T03:** `critical` (zeros, extrema, inflections, horizontal asymptotes) and the `critical-points` analyzer, whose annotations become insight nodes; the 40-curve suite lists every critical point. Code `SNR-ENG-420`.
- **RFC-0007** (#426), accepted by the coordinator with three amendments, and **C03-T04:** Score IR version 2 per Score, four function-cue earcons, CURVASONA's `curvasona.cues` track, ADR-0029. The golden case `function-cues` waits for RAM to render its reference.
- **C03-T05:** the `Audify` event, CURVASONA's `audify` encoder with the SDR-31 calculator, the render engine's resampler and buffer voice; codes `SNR-ENG-460` to `465`; F-195.

## Decisions

| Decision | Why | Record |
|---|---|---|
| The `expr` language is specified by an ADR, not only in 07 | What `function.expr` accepts is part of the spec language (AGENTS.md rule 11); the key exists, so an ADR specifies it instead of an RFC adding it (coordinator) | [ADR-0028](../../decisions/0028-function-expression-language.md), accepted 2026-10-31 |
| CURVASONA parses expressions itself and gives exmex only a fully parenthesized form | exmex binds unary minus tighter than `^` (`-2^2` is 4), its errors are not localizable, and the sandbox needs a closed set of names and depth limits before any third-party parser sees the text | [F-190](../../research-paper/findings-log.md#f-190--exmex-alone-reads--22-as-4-so-curvasona-parses-expressions-itself); 07 CURVASONA "As built (C03-T01)" |
| `log` and `sign` are not in the language | `log` means ln in some books and log10 in others; exmex's `signum` gives sign(0) = 1 | 07 CURVASONA; `SNR-ENG-401` help |
| `dy` falls back to central differences where exmex has no derivative | `abs`, `floor`, `min`, `cbrt` and `atan2` have none in exmex; a numerical `dy` is accurate where the function is smooth, and C03-T02/T03 handle the kinks and jumps | `SNR-ENG-405` (Info) |
| Singular points come from the expression's guards, not from denser sampling | The language is closed, so every discontinuity sits at a zero of a known sub-expression; finding those zeros cannot miss a pole between samples, while denser rows would change the meaning of `samples` and the pace | 07 CURVASONA "As built (C03-T02)" |
| An empty row at each pole or hole between samples | Without it a glide sweeps from +∞ to −∞ across a pole | 07 CURVASONA |
| The analyzer recomputes features from the expression in the table's metadata | It gets only the data and the `analysis` object; recomputing (rather than reading a stored list) means a project file cannot claim points the function does not have | 07 CURVASONA "As built (C03-T03)" |
| Rows at zeros, extrema and inflections | The glide reaches the exact extreme value, and each insight lands on its own point, not the nearest sample | 07 CURVASONA |
| Derivatives on CURVASONA's own tree, exmex for evaluation only | exmex's `partial` overflows a 2 MB stack on allowed input, an uncatchable crash from untrusted input (F-192) | 07 CURVASONA "As built (C03-T03)" |
| A merged earcon's `src` is its highest-priority feature's row; `cue_log` names them all | `Earcon.src` is one `RowRef`; refines RFC-0007 amendment 1 (coordinator) | [ADR-0029](../../decisions/0029-function-cues-and-audification.md) |
| E-ASYMPTOTE is a swell, not a sweep | The render engine's noise filter is fixed per earcon; a swept filter waits for the listening check | keyboard and navigation §11 |
| Audification resamples with a `libm` windowed-sinc, not rubato | Golden audio needs bit-identical renders across CPUs (F-039, ADR-0013); rubato's FFT path runs through rustfft's per-CPU SIMD code | [ADR-0030](../../decisions/0030-deterministic-audification-resampler.md), F-195 |
| Without `k` or `band`, k puts the band's top at 4 kHz | RFC-0001 lets `k` default "from the data band" but names no target; no study gives one; approved as SDR-44 (INFER) | design-rules SDR-44, F-196 |
| Holes have no extrema | `sin(x)/x` is undefined at 0; calling 0 its maximum would describe a value it never takes | 07 CURVASONA |
| The crate is `publish = false` for now | A new crate's first publish is the owner's (trusted publishing), and nothing published depends on it until C03-T07 | crate `Cargo.toml` |
| C03-T07: CURVASONA is published, as the 17th crate | The facade depends on it now; experimental like PLOTSONA, first publish by the owner | release-process, `release-plz.toml` |
| C03-T07: the facade adds CURVASONA only to compiles that use it | A registered context provider is recorded in every Score's header and hides `SNR-COMP-023` (F-197) | `crates/sonarithm/src/api.rs` |
| C03-T07: functions open in the app through the spec, with no IPC change | `spec_set` with a `function` source and `compile` already do it headless; a `function_open` command would change the IPC protocol (ADR-0017) and waits for the desktop function input (C03-T08) | app scenario `a_function_compiles_headless` |
| C03-T07: `Expr` boxes exmex's compiled form | Unboxed it was 19 KB, and debug builds overflowed the CLI's 1 MB main thread while sampling (F-198) | `expr.rs` |
| C03-T08: a function opens as a dataset (`function_open`) | The cursor, table, plot and readout key on open datasets; the analyzer and the cues read the function from the table's metadata, so a `dataset` source works unchanged | ADR-0017 "Functions" |
| C03-T08: saving a project with a function fails (`SNR-APP-089`) | The project format cannot store a function's definition, and saving its samples would lose it; a project-format amendment comes first (AGENTS rule 11) | coordinator, 2026-11-01 |
| C03-T08: the calculator shares the encoder's grid code | So the calculator and a compile can't disagree | `audify::readout` |
| C03-T07: the quick function spec lasts 8 s | The length of 04 §6.3's example; no rule covers how long a function's sweep should last (TODO(verify), HP-21) | `FUNCTION_DURATION_S` |
