- **T10:** the PB-05 criterion benchmark; four fuzz targets and their nightly job; fixes for what fuzzing found.

## Decisions

| Decision | Why | Record |
|---|---|---|
| File-path sources and the zstd codec are default features (`fs`, `zstd`); the workspace depends on `sonarithm-data` without defaults and `cargo xtask wasm-check` builds it with `--no-default-features` | "Partial (no fs)" in 02 §2; zstd builds C code that needs a wasm-capable clang | 02 §2; tech-stack |
| Text cells from every format go through one type inference | The same messy column behaves the same in CSV, JSON and spreadsheets | 03 §3.1 implementation note |
| Missing-value tokens (`NA`, `-`…) apply to typed columns only | A text value such as the country code `NA` is never lost | `infer::text` docs |
| Ordinal text is stored as `Dictionary<UInt8, Utf8>` in rank order | The rank travels with the data without a new metadata key | 03 §3.1 implementation note |
| Row-level provenance propagation follows 03 §4 rule 2 literally; aggregates record `derived`, and an estimated input makes the result an estimate of that class | Provenance is per row; the class itself is the flag rule 2 asks for | 03 §4 propagation table |
| rhai's dependency `smartstring` is unmaintained (RUSTSEC-2026-0249); the advisory is ignored with a reason and tracking issue | Not a vulnerability; rhai is the adopted expression language | `deny.toml`, #115 |
| Third-party decoder panics become errors (`catch_unwind`), and declared IPC sizes are validated before decoding | Library code must not panic on any input (coding-standards §4.1) | F-071 |

## Problems and how they were solved

| Problem | Cause | Resolution |
|---|---|---|
| The wasm32 build of `sonarithm-data` failed with zstd | `zstd-sys` needs clang for wasm32 | `zstd` feature, `--no-default-features` in the wasm check |
| arrow-ipc requested 2^58-byte allocations on fuzzed input | It trusts declared body and uncompressed lengths | Framing, buffer-bound and size checks before decoding (F-071) |
| calamine panicked and allocated whole bounding boxes | `Range::range` on a zero-width range; dense ranges from sparse cells | XLSX cells streamed, bounding box checked against the limits, no `Range::range` (F-071) |
| libFuzzer on Windows reports caught panics as crashes | Its SEH handler sees the panic exception first | Containment checked by unit tests; the two decoder targets are meant for the Linux nightly run |
