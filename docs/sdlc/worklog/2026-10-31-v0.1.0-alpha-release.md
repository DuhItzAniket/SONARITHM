## Goals

- Publish v0.1.0-alpha from the release commit, following release-process "First release: owner steps".

## What was done

- Published the 16 crates to crates.io from `0c9fdd9` with `cargo publish --workspace --locked`, in rounds that followed the crates.io new-crate rate limit (2026-10-30). The owner set up trusted publishing on every crate afterwards and revoked the token.
- Rehearsed the PyPI upload on TestPyPI with a manual `wheels.yml` run (`0.1.0a0`, three wheels and the sdist); installed and imported it in a clean venv.
- Tagged `v0.1.0-alpha` on `0c9fdd9` and created the GitHub pre-release with the changelog section as notes. The tag's `wheels` run published to PyPI; `release-binaries` attached attested archives for Windows, Linux and macOS.
- Zenodo minted DOI [10.5281/zenodo.23816603](https://doi.org/10.5281/zenodo.23816603) from the release.
- Checked on Windows: `pip install --pre sonarithm` imports `0.1.0-alpha`; `cargo install sonarithm-cli --version 0.1.0-alpha --locked` builds from crates.io and prints `sonarithm 0.1.0-alpha`; `gh attestation verify` passes on the Windows archive.

## Decisions

| Decision | Why | Record |
|---|---|---|
| Tag only after the TestPyPI rehearsal passed | A PyPI version cannot be uploaded twice | no ADR needed: release-process already asks for the rehearsal |

## Problems and how they were solved

| Problem | Cause | Resolution |
|---|---|---|
| crates.io rejected uploads with 429 after the first few crates | New-crate rate limit: a burst, then one new crate about every 10 minutes | Published in rate-limited rounds until all 16 were up |
| The first TestPyPI rehearsal was cancelled before it ran | `wheels.yml` put manual runs and pushes to `main` in one concurrency group, so a push replaced the waiting run | #410: manual runs get their own group |
| `no_alloc_device` failed on busy Windows runners | The test counted callbacks over a fixed 3 s | #408: it runs until it has seen enough callbacks (up to 30 s) |
