## Decisions

| Decision | Why | Record |
|---|---|---|
| `roxmltree` for Office chart XML and SVG, not `quick-xml` | It refuses DTDs by default and caps nodes; one XML parser keeps the fuzzing surface small | C01-T02 table |
| `zip` with Deflate only | No AES, bzip2, LZMA, zstd or C code in an engine crate; the budgets are checked before and during inflation | C01-T02 table |
| PLOTSONA reads PDF objects itself | `lopdf` brings crypto and random-number crates; `hayro-syntax` needs Rust 1.92 | [F-160](../../research-paper/findings-log.md) |
| The "time" budget is a step count | A clock in an extraction path breaks determinism (ADR-0013); a step count stops a file at the same point everywhere | 07 PLOTSONA "As built" |
| The compression-ratio check applies above 1 MiB, at 200:1 | Small runs of XML compress far better than whole documents; a ratio checked against the entry's whole compressed size trips once the inflated bytes pass 200 times it (an 8 MiB zero bomb stops at about 1.6 MiB) | `container.rs` tests |
| Chart tables always keep their provenance columns | An exact chart's class is stated, not implied by absent columns (rule 7) | 07 PLOTSONA "As built" |
| v0.2 sections that were free-form in v0.1 (`calibration`, `scale`, `tuning`) stay JSON in the spec type and are read by validation | RFC-0004 Q14: a v0.1 value v0.2 rejects must still read and fail validation at its pointer, not fail parsing | `sonarithm_spec::v02` docs |
| `just` tuning rejected for now | ADR-0021 (Q13): it ships only with a cited ratio table, which C04-T02 owns | `SNR-SPEC-044` hint |
| v0.2 defaults fill only v0.2 documents | A v0.1 document's canonical form, and so its hash, must not change (RFC-0004 §9) | `defaults::v0_2` |
| Calibration residual = RMS anchor distance as a share of the axis; confidence = 1 − 10 × residual | Comparable across axes and tiers; no study calibrates extraction confidence (notes/06 §8), so the formula is a convention to check on the C01 corpus | 10 §3.1 "As built" |
| Percent labels read as written (`50%` is 50) | Libraries disagree on whether the data is a fraction; the C01 corpus decides per library, never a silent rescale | `calibrate::ticks` docs |
| The workbook is preferred to the chart cache, but only after its parts pass the budgets | It is the data the chart was built from (the plan's "embedded workbook preferred"); calamine has no budgets of its own, so every part is inflated once under PLOTSONA's budgets first | 07 PLOTSONA "As built (C01-T05)" |
| DOCX corpus charts reuse the PPTX chart part and workbook | python-docx has no chart API; Word reads the same DrawingML chart part | `generate/office.py` |
| JavaScript chart options are read as literals, with `Date.UTC` the one allowed expression | Highcharts pages write options as JavaScript, not JSON; `Date.UTC` with number literals is a pure constant, anything else would be running code (OD-25) | 07 PLOTSONA "As built (C01-T06)" |
| Vega-Lite aggregates are computed and marked `derived` | The chart draws the aggregate, not the rows; 03 §4 gives aggregates the `derived` class | `chartjson::vegalite` |
| SVG labels are snapped to tick or grid lines | Text anchors sit beside their ticks (baseline shifts, rotations, gaps); lines give exact positions | 07 PLOTSONA "As built (C01-T07)" |
| Vector-tier error is measured against the chart's largest value | Digitizing error is a share of the axis, not of each value; a small value read 0.1 px off would otherwise fail | `corpus.rs`, F-163 |
| Pies give shares in percent | A pie's geometry holds no absolute values | `SNR-ENG-363` |
| SVG and PDF share one scene reader (`vector`) | A PDF page and an SVG are the same kind of drawing; one axis and mark reader means one set of fixes and one accuracy | 07 PLOTSONA "As built (C01-T08)" |
| v0.2 sections that were free-form in v0.1 (`calibration`, `scale`, `tuning`) stay JSON in the spec type and are read by validation | RFC-0004 Q14: a v0.1 value v0.2 rejects must still read and fail validation at its pointer, not fail parsing | `sonarithm_spec::v02` docs |
| `just` tuning rejected for now | ADR-0021 (Q13): it ships only with a cited ratio table, which C04-T02 owns | `SNR-SPEC-044` hint |
| v0.2 defaults fill only v0.2 documents | A v0.1 document's canonical form, and so its hash, must not change (RFC-0004 §9) | `defaults::v0_2` |
| A template merges with the spec as written, not the resolved spec | Defaults fill sections the author never wrote; merging after defaults would make every template section look replaced | 05 §2 "Template expansion" |
| Template binding lives in `sonarithm-data` | NUMISONA's and PLOTSONA's templates must bind by the same rule (03 §3.4), and engines may not depend on each other | `sonarithm_data::slots` |
| Pie and stacked-bar templates are experimental | No design rule covers parts of a whole or stacked segments; they warn (`SNR-ENG-380`) and are TODO(verify) | 07 PLOTSONA "Chart-type templates as built" |
| Importers write the `template` key, not tracks | The chart-type templates already hold the default design (x → time, y → pitch, colour → timbre); an imported spec stays short and changes with the templates | 04 §9 |
| Importer examples are written, not copied from the Vega-Lite gallery or MAIDR's repository | No third-party chart file enters the repository without a recorded licence (C01-T11) | `tests/import/generate.py` |
| RMS-F1 matches keys exactly | A stricter form than `DePlot`'s edit-distance matching, so a pass here is also a pass there; the difference is noted (F-167) | `accuracy.rs` docs |
| The accuracy job runs `cargo test` on one crate | It needs no nextest install and finishes in seconds; the report is the artifact the C01 exit cites | `ci.yml` `chart-accuracy` |
| No HTML parser | Only the text of `<script>` blocks is needed, and no script runs (OD-25) | C01-T02 table |
