## Goals

- Build NUMISONA, the data → sound parameter-mapping engine, with the design-rule defaults and a named test for every rule it owns.
- Import Erie specs (subset) and render the gallery subset; meet PB-04.

## What was done

- **T01:** `scale`: linear, log, symlog, sqrt, pow, quantile, band and ordinal, with auto, zero-based and explicit domains, d3-style `nice` and off-scale reporting; monotonicity and range property tests.
- **T02:** `pitch`: log-frequency (default), linear, mel, ERB-rate and Bark spaces; the 400–1400 Hz default and 65–1480 Hz expanded ranges; ranges in Hz, MIDI or cents.
- **T05:** the psychophysical scale `f = f_ref · (d / d_ref)^(1/m)`, labelled as guidance; a test reproduces Smith & Walker's dollar mapping.
- **T03:** `data/concepts.toml` (16 rows, each citing evidence and Walker 2007 counts) and polarity resolution (explicit → profile → concept → generic), the profile's one-key flip, and the first `SNR-ENG` codes.
- **T08:** `import::erie`, written from Erie's documentation; an 8-spec gallery subset imports as valid specs with a report of every approximated or unmapped construct.
- **T04:** the `Numisona` engine and its `tone` and `glide` encoders: filters keep original rows, time order and the three paces, every channel, redundant taps and duration (A11Y-13), timbre per category (SDR-25), missing values, confidence on notes; synthetic example datasets; snapshots. Core's `TrackRequest` gained the substrate, field semantics, missing-value treatment and mode.
- **Compiler data (#152):** `DataBundle` as the compiler's data with spec transforms applied by the data layer, and the `Platform` engine for inline and file sources.
- **T06:** the experimental `auto` mark (tones up to 10 events/s, a glide above), reported as experimental on every use.
- **T07:** six templates (line, bars, scatter, histogram, box plots, heat-map row scan) with slot binding; each renders every compatible example dataset through the render engine.
- **T09:** the rule-conformance suite with a coverage check against the design-rules catalogue, the SDR-21 volatility advice, the Erie gallery render, and the PB-04 criterion benchmark.

## Decisions

| Decision | Why | Record |
|---|---|---|
| Polarity flips the scale position before the pitch space, so a flip mirrors pitches in the space's coordinate | Equal data steps stay equal steps in the chosen space for both polarities; in log-frequency it is the cents mirror of invariant 4 | F-080; 05 §4.2 |
| The concept table and the polarity profile live in NUMISONA, not `CompileContext` | Core carries no engine data; the profile is set on the engine (`Numisona::with_profile`) | 05 §3 note |
| `TrackRequest` carries the substrate, `data.fields`, `data.missing` and the mode | An encoder cannot place notes without the substrate, which NUMISONA owns | ADR-0014 (additive), 05 §3 note |
| `duration` pace spaces n points evenly over the duration; `secondsPerUnit` places them in proportion to the time field | `pointsPerSecond` and `duration` are both rank-based; only `secondsPerUnit` names units of the time field (RFC-0001 §5) | `encode` module docs |
| Proposal ranges for duration (0.1–0.3 s), taps (1–8) and loudness (−24 to −12 dB) mappings | No rule fixes them; A11Y-13 needs one | F-082 |
| Templates are spec builders; box plots compute quartiles themselves | Spec v0.1 reserves `template` and has no quartile aggregate | `templates` docs; 07 |
| The Erie importer lives in NUMISONA and works from documentation only | 07 assigns `import::erie` to NUMISONA; the brief forbids copying Erie code | `import::erie` docs |
| SDR-21 is an advice, not an automatic change | The encoder never alters data silently; beyond the three reversals studied it suggests smoothing or a slower pace | F-084 |

## Problems and how they were solved

| Problem | Cause | Resolution |
|---|---|---|
| Declared field metadata vanished from the example datasets | `ReadOptions::without_inference()` drops declared `fields` too: `finish` applies them only through `infer_table` | Examples keep inference on (declared fields win); reported to A04 in the T04 PR |
| Conflicts on every rebase in status.md, the traceability matrix, CHANGELOG and Cargo.lock | Four sessions merging in parallel; stacked local branches after squash merges | A scripted resolver that keeps main's side and applies A06 rows; a second script that rewrites the A06 task table |
| The A05 render lines in CHANGELOG had landed under the A06 heading | An append at the end of the list during a parallel merge | Moved back under "Render engine (phase A05)" in #152 |
| A smoothed temperature series still reversed direction | A 30-day moving average leaves small wiggles; reversal counting has no hysteresis | The SDR-21 test uses a zigzag that a 2-point average makes monotone; hysteresis is a follow-up for ECHOMETRIC's lint |

## Findings to log

- F-082: three proposal ranges for duration, taps and loudness mappings.
- F-083: PB-04 compile times.
- F-084: the SDR-21 volatility threshold rests on the reversal counts studied by Nees & Walker 2008.
