# 0011 · Typed IPC via ts-rs and JSON Schema

## Context and problem statement

The Rust host and the TypeScript UI exchange dozens of message types (commands, results, errors, channel payloads), and the spec must also be editable with schema validation. How do we keep the two sides in sync?

## Decision drivers

* A single source of truth in Rust.
* Stable, released tooling.
* JSON Schema for the spec editor (CodeMirror) and for external users.

## Considered options

* **ts-rs** (TypeScript types from Rust types) + **schemars** (JSON Schema)
* specta / tauri-specta (typed commands)
* Hand-written TypeScript types
* Protocol Buffers / FlatBuffers

## Decision outcome

Chosen option: **ts-rs for IPC types and schemars for JSON Schema**, generated by `cargo xtask codegen` into `packages/ipc/src/generated/` and `schemas/`. CI fails when the generated output is stale. A thin hand-written typed client wraps `invoke` and channels.

### Consequences

* Good: both tools are stable (ts-rs 12, schemars 1.x); compile-time agreement between UI and host.
* Bad: command signatures (names and argument lists) are not generated. The typed client is small and reviewed, and a contract test exercises each command.
* specta and tauri-specta are still `2.0.0-rc.25` ([notes/04 §11](../research/notes/04-rust-core-stack.md)). Revisit if they stabilize.

### Confirmation

B01: every command has a generated request/response type and a contract test. The codegen staleness check is in CI.
