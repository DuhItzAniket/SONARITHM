# 0015 · Spec v0.1 frozen per RFC-0001

## Context and problem statement

[ADR-0005](0005-declarative-spec-and-score-ir.md) chose a declarative JSON spec compiled to a canonical Score IR. Its confirmation step was to freeze the first public version of the spec through an RFC. [RFC-0001](../rfcs/0001-spec-v0.1.md) proposed that freeze. It sets the exact key set, value shapes and units, defaults with their design-rule IDs, validation codes, the canonical form used for the spec hash, and the version and migration rules. It also raised 21 open questions, each with a proposed resolution.

## Decision outcome

**RFC-0001 is accepted as written, including all 21 proposed resolutions** (owner decision, 2026-10-19). `specVersion: "0.1"` is frozen. The most consequential resolutions:

- Durations are never bare numbers: always `{ "s": n }` or `{ "ms": n }` (Q20).
- `pace` is optional and defaults to 3 points/s (SDR-19) (Q11). `mark` has no default, because `auto` rests on the `INFER` rule SDR-20 (Q16).
- The default `seed` is `0`. Seeds range over 0 … 2^53 − 1 so every JSON implementation round-trips them exactly (Q6, Q7).
- `specVersion` is the string `"MAJOR.MINOR"` (Q9). `x-` vendor keys are top-level only and are part of the spec hash (Q5, Q8).
- Every mark uses `loudness` (relative dB); there is no `gain` channel (Q2). v0.1 has no `speech` mark (Q3).
- Engine keys not yet specified (`concepts`, `navigation`, `template`, `instruments`, `lint`, `lens`, `models`) are reserved and rejected in v0.1 (Q12).

### Consequences

- Good: A03-T06..T11 (spec types, JSON Schema, validation, canonicalization, fuzzing, doc-example tests) implement one fixed contract.
- Good: the spec hash recorded in render manifests ([ADR-0013](0013-determinism-and-provenance.md)) has a stable definition.
- Neutral: adding an optional field or enum value is a minor version. Renames, removals, reinterpretations, new top-level sections and new substrate, mark or channel kinds need a new RFC ([04 §7](../architecture/04-sonification-spec.md#7-versioning-and-compatibility)).

### Confirmation

A03 exit criteria: every documented spec example validates against the generated schema, the schema is regenerated and diff-checked in CI, and the spec parser survives at least an hour of fuzzing.
