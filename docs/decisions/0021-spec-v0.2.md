# 0021 · Spec v0.2 per RFC-0004

## Context and problem statement

Spec v0.1 ([ADR-0015](0015-spec-v0.1-frozen.md)) reserves the keys `template`, `instruments` and `lint`, accepts any object as `chart.calibration`, and leaves AXONOTE's scale and tuning names to C04. Stage C's engines need all of these (PLOTSONA's templates, calibration and corrections; AXONOTE's quantizer and instruments; ECHOMETRIC's lint). AGENTS.md rule 11 forbids defining them in code. [RFC-0004](../rfcs/0004-spec-v0.2.md) proposed spec v0.2 with 15 open questions, each with a proposal.

## Decision outcome

**RFC-0004 is accepted with three amendments** (coordinator under the owner's delegation, 2026-10-26; 7-day FCP waived). `specVersion: "0.2"` is a minor version. The most consequential points:

- `template: { id, bind }`. A template's sections are replaced whole by sections the spec writes; the spec's `transform` runs before the template's; `tracks` is optional with a template; `template` stays symbolic in the canonical form (Q2, Q3).
- `instruments` maps names to definitions, starting with `soundfont` (`path`, `bank`, `program`). A defined name wins over a built-in preset, with an `Info` diagnostic. Mallet stays the default (SDR-29). SoundFonts are allowed in every mode (Q4, Q5).
- `lint` sets levels by design-rule ID and takes suppressions with a required reason. Every rule, MUST ones included, can be lowered or suppressed, and the suppression is always reported. **Hearing-safety protections are not lint rules, and no spec can turn them off**: the master true-peak limiter at −1 dBTP, the start-up gain ramp, and SDR-22's onset and offset ramps (Q6–Q8, amendment 2).
- `chart.calibration` is typed: 2D anchors in the source's own coordinates, at least two per axis (Q9). `chart.corrections` takes inline edits (`add`, `move`, `delete`, `retype`), found by series, index and a `was` guard (Q10, Q12). **`corrections.path` stays reserved** for RFC-0005 (Q11, amendment 3).
- `music.quantize`: scale names `"<tonic> <mode>"` (14 modes, the pentatonic and blues scales included) or custom cents; tunings `12-TET`, custom cents, and `just` only with a cited ratio table (Q13).
- **A v0.2 reader reads `"0.1"` documents as they are**, with no migration warning, and their spec hashes do not change. This supersedes RFC-0001 §13's migrate-and-warn for the 0.1 → 0.2 step only (Q1). `sonarithm spec migrate` rewrites a file to 0.2 by changing only `specVersion`.
- **Every committed spec stays valid** under v0.2 reading, whichever version it declares. Values v0.2 rejects get a validation error, never a guessed rewrite (Q14, amendment 1).

### Consequences

- Good: C01-T09, C02-T06, C04-T02 to T04 and C05-T07 to T08 implement one fixed contract.
- Good: spec hashes in existing render manifests and A08 study logs stay valid.
- Neutral: the reader keeps a table of which keys each minor version adds, so a v0.2 key in a `"0.1"` document gets `SNR-SPEC-004` with a hint.
- Bad: `just` tuning may slip to a later minor version if no cited table is found.

That includes the corpus test over every committed spec and the doc-example test. No code reads the new keys before then.
