# Code of conduct

> **Status:** Baseline v1 (2026-10-18). **Owner:** Project lead.
> Related: [Contributing](CONTRIBUTING.md) · [Governance](GOVERNANCE.md) · [Security policy](SECURITY.md)

## Adoption

SONARITHM adopts the **[Contributor Covenant, version 3.0](https://www.contributor-covenant.org/version/3/0/code_of_conduct/)** by reference. That text is this project's code of conduct. This file does not restate it; it supplies the project-specific details the covenant asks adopters to fill in: scope, how to report, and how the project addresses harm.

Version 3.0 was chosen because its enforcement model ("Addressing and Repairing Harm") is restorative, which suits a research community that works closely with blind and low-vision co-designers ([announcement](https://ethicalsource.dev/blog/contributor-covenant-3); [research notes 07 §5](docs/research/notes/07-engineering-publication.md)).

## Scope

The code of conduct applies in every SONARITHM community space and whenever someone represents the project:

- This repository: issues, pull requests, reviews, discussions, commit messages and wiki pages.
- Any chat channel, mailing list or forum the project creates later.
- Co-design sessions, user studies and workshops run by the project. For study participants, the approved ethics protocol applies as well.
- Conferences, demos and other events where a person represents SONARITHM.

SONARITHM is built with and for blind and low-vision people. The moderators treat dismissing or ridiculing access needs, or refusing reasonable accommodations in project spaces, as harm under the covenant.

## Reporting

Report privately to the project lead, [@DuhItzAniket](https://github.com/DuhItzAniket), through GitHub:

1. **For a specific comment, issue, pull request or discussion:** use GitHub's "Report content" option on that item and choose to report it to the repository maintainers. (Maintainer reports are enabled in the repository's moderation settings during phase A01.)
2. **For anything else:** use a contact option listed on the project lead's GitHub profile. If none fits, open a minimal issue that says only that you want to raise a code-of-conduct concern privately. Put no details in it; the project lead will reply with a private channel.
3. **If the concern is about the project lead:** report it to GitHub through its "Report abuse" option until a second moderator exists. [GOVERNANCE.md](GOVERNANCE.md) will name additional moderators as maintainers join.

The project has no legal entity yet, so there is no dedicated conduct contact. One will be added here when the project has a legal home.

Reports are handled confidentially. Only the people who need to act on a report see it. Nobody is penalised for a report made in good faith, and retaliation against a reporter is itself a violation.

## Addressing and repairing harm

**Moderators.** During Stages A and B the project lead is the moderator. When maintainers join, moderation passes to the maintainers as described in [GOVERNANCE.md](GOVERNANCE.md#roles). A moderator who is involved in a report, or has a conflict of interest, takes no part in handling it.

**Process.**

1. Acknowledge the report within 3 business days (target).
2. Gather the facts, including from the person reported where that is safe.
3. Decide on a response using the covenant's four-step ladder: **Warning**, **Temporarily Limited Activities**, **Temporary Suspension**, **Permanent Ban**. Steps can be skipped for serious harm. Where possible, the response includes a way to repair the harm.
4. Tell the reporter the outcome, as far as privacy allows.
5. Keep a private, minimal record of the report and the decision. Do not publish names unless a ban requires public notice.

**Appeals.** A person subject to a decision can ask for it to be reviewed by moderators not involved in the original decision. Until the project has more than one moderator, the project lead reviews the decision once more, and GitHub's own policies remain available.

**Research participants.** Concerns about how a study is run can also go to the ethics board named in the consent materials.
