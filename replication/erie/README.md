# Erie gallery subset

> **Source:** Kim, H., Kim, Y.-S. & Hullman, J. (2024). Erie: A declarative grammar for data sonification. *CHI '24*. [doi:10.1145/3613904.3642442](https://doi.org/10.1145/3613904.3642442) (`kim2024erie`); findings F-007 and F-081.

These specs are generated by `cargo xtask replication`: NUMISONA's Erie importer (A06-T08, SDR-05) translates the eight Erie fixtures in [`crates/engines/sonarithm-numisona/tests/erie/`](../../crates/engines/sonarithm-numisona/tests/erie/README.md) into spec v0.1. The fixtures are modelled on examples of the Erie editor gallery and were written for SONARITHM from Erie's documentation; no Erie code or gallery file was copied, and their data is synthetic. The regression-residuals fixture plays two specs in sequence, so the eight fixtures give nine specs.

## What matches and what does not

The importer reports, per fixture, every construct it approximates or cannot express: 19 across the subset (F-081). Spec v0.1 expresses 8 of Erie's 15 documented encoding channels, and neither sequential composition nor intervals. The main departures audible here:

- **Timbre presets.** Instruments the render engine does not have, such as Erie's piano in `frequency.json`, fall back to the default mallet timbre with an `SNR-RENDER-001` warning.
- **Unstated defaults.** Erie's documentation does not state its default pitch range or band, so where a fixture relies on them the specs use SONARITHM's defaults (400–1400 Hz, SDR-08).
- **Composition.** A sequence is two specs played one after the other; an overlay is two tracks in one spec.

The gallery shows that each imported spec compiles and renders reproducibly. It does not show that it sounds like Erie's Web Audio rendering of the same example.
