# Changelog

All notable changes to SONARITHM are documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/). Versions follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html) with the pre-1.0 rules in the [release process](docs/engineering/release-process.md#versioning-policy). The spec version (`specVersion`) is versioned separately.

From phase A07, release-plz maintains this file: it generates each release's entries with git-cliff from Conventional Commit messages and proposes them in the release pull request. Edit wording in that pull request, not after the release. Until A07, entries are written by hand.

## [Unreleased]

### Added

- Functions in the command line and Python (C03-T07): `sonarithm quick --function "sin(x)/x" --domain -20,20` plays a function as a glide with earcons at its zeros, extrema and asymptotes, and first prints its critical points as text, such as "Local maximum at x = 1.5708, y = 1.". `sonarithm inspect` lists a function spec's critical points and prints an audification's speed-up, length and audible band. Python gains `read_function`. The `sonarithm-curvasona` crate is published as experimental.
- Smoke-run diagnostics (#436): a desktop smoke run that hangs or whose page fails to load now ends with a failing report that names the stuck check, instead of waiting until CI's time limit.
- Zoom and pan on the plot (B04-T07): drag across the plot to zoom to that range, or use the Plot view toolbar (Zoom in, Zoom out, Reset zoom, Pan left, Pan right) or Ctrl+Plus, Ctrl+Minus and Ctrl+0 (Cmd on macOS). Zooming keeps the cursor in place, and the shown range is displayed and announced.
- The Plot tab (B04-T06): it draws the dataset as a line, with the shared cursor as a dashed crosshair. Clicking the plot moves the cursor to the nearest point, which is announced, and the table and the Status region follow.
- Measured output latency (B04-T04): Preferences takes the latency you measured for the selected output device, in milliseconds, and the playhead uses it instead of the system's estimate. It is kept only in your local settings.
- One cursor (B04-T06): the row you focus in the data table is the cursor that every view shows. It is selected in the table, and the Status region shows its data row and its place (dataset, series, segment, point) as a breadcrumb. Moving it from the table does not repeat what your screen reader already reads, and nothing moves your focus when the cursor moves elsewhere.
- The playhead (B04-T04): it moves smoothly over plots, extrapolated from the audio engine's clock anchors, with no redraw of the data and no per-frame message from the engine.
- The data table (B04-T05): the Table tab lists a dataset's rows with each row's number in the whole table, a provenance column that names estimates, and sorting by Enter on a column header. It loads rows in windows of 1,000, says which rows are loaded, and moves between windows with the arrow and page keys, Ctrl+Home and Ctrl+End (Cmd on macOS), and "Go to row…" in the command palette.
- Nightly desktop builds for testers (B01-T09): unsigned Windows, macOS and Linux installers of the latest `main`, as artifacts of the `desktop-nightly` workflow. They are not releases and have no updater; release-process explains how to install them past the unsigned-app warnings.
- Dense views (B04-T02): waveforms, spectrograms and lines of a million points draw with WebGL2, or with Canvas2D where WebGL2 is unavailable, and are drawn once, so a moving playhead never redraws the data.
- Audio preferences and stop all audio (B01-T08): Ctrl+Comma (Cmd+Comma) opens Preferences, where you pick the output device and set SONARITHM's own volume in decibels, which never changes the system volume. Ctrl+Period (Cmd+Period) stops all sound and speech from anywhere, even inside a dialog. When the audio device changes or fails, SONARITHM says so in words.
- Start-up (B01-T07): the app opens with the keyboard focus in the Project region, and never waits for the audio device, which opens on the first play.
- Plots (B04-T01): `@sonarithm/viz` draws line charts whose eight series colours are tuned per theme to stay visible and distinguishable for colour-blind viewers, each with its own dash pattern; a plot is one named, described image for screen readers. Spectrogram colormaps viridis and magma are included.

### Fixed

- The desktop app starts and draws plots under a POSIX "C" locale (for example `LANG=C` on Linux), which made the plot library throw while loading (#436).

## [0.1.0-alpha] - 2026-10-30

The first public alpha. It contains everything merged up to 2026-10-30 and is released as 16 crates on crates.io, the `sonarithm` command line tool (crates.io and release archives) and the `sonarithm` Python package (abi3 wheels on PyPI). The Rust core, the command line tool and the Python package compile specs to Scores, render them to WAV and FLAC with a provenance manifest, and play them.

- **Experimental and unstable:** the Stage B and C library code in `sonarithm-audaxis` (navigation, context cues, announcements, profiles), `sonarithm-sonotrace` (live streams, transport, monitoring), `sonarithm-plotsona` (chart extraction) and `sonarithm-i18n` (message catalogues and locale formatting). These crates are published because the facade depends on them. Their APIs, and the parts of the facade that expose them, can change in any release before 1.0 and are not covered by semantic versioning until then.
- **Not in this release:** the desktop app (`apps/desktop`, `sonarithm-desktop`, `sonarithm-app`, `@sonarithm/*` packages), `sonarithm-speech` and `sonarithm-stream` are in the repository but not published. Their entries below describe work in progress.

### Added

- The transport toolbar (B01-T05): Play and Pause, Stop and Loop in the top bar follow what the audio engine reports, and are also in the command palette. Nothing plays until you press Play.
- The command palette (B02-T07): Ctrl+Shift+P (Cmd+Shift+P on macOS) lists every available command with its shortcut; typing filters the list and the number of matches is announced. Shift+F1 lists the shortcuts that work where the focus is.
- Announcements in the desktop app (B03-T04): what SONARITHM says reaches the screen reader through live regions by default, or through Windows UI Automation notifications with the `speech.announcer` setting set to `native`; every announcement also appears in the Status region's log. Announcing never moves the keyboard focus.
- Open a chart and hear it (C01-T12): `sonarithm inspect figure.svg` (and XLSX, PPTX, DOCX, chart JSON, HTML pages, vector PDF) prints what was extracted, a summary such as "36 points: 0 exact, 36 calibrated, 0 estimated, median confidence 0.99", and the Score its chart-type template gives; `--json` prints the report. Python has `sonarithm.read_chart(path)`, the Rust facade `read_chart`, and the app opens chart files as datasets. The default engines now include PLOTSONA.
- The desktop app's frame (B02-T06): the top bar, Project, Workspace, Inspector and Status regions, each a landmark. F6 and Shift+F6 move between them in the same order at every window size. The side regions resize from the keyboard and collapse to a single "Expand" button; narrow windows show one region at a time with a region switcher.
- Vega-Lite and MAIDR import (C01-T10): `sonarithm_plotsona::import` turns a Vega-Lite specification or a MAIDR document into a SONARITHM spec with the chart's data and the chart-type template its mark calls for (x to time, y to pitch, colour to timbre), with a report of everything it could not map exactly. Data on the network is never fetched.
- Templates by name (C01-T09): a v0.2 spec can say `"template": { "id": "chart-bar" }` instead of writing its tracks, and SONARITHM binds the template to the data's fields (by role, then by kind; `bind` picks fields by hand). NUMISONA's six templates and PLOTSONA's new chart-type templates (`chart-line`, `chart-bar`, and the experimental `chart-stacked-bar` and `chart-pie`) are available; a section written in the spec replaces the template's, and the compiler reports the binding and which sections came from the template. Every chart in the extraction corpus compiles through the template its type calls for.
- The desktop app's shell (B01-T03): `apps/desktop`, a Tauri 2 window over the same app core the tests drive, opening an empty workspace. It loads nothing from the network and refuses to navigate anywhere else; browser shortcuts such as F5, Ctrl+R, Ctrl+F, F7, F12 and Alt+Left do nothing in it; data views reach the UI as binary. Not released yet: installers come with the nightly builds (B01-T09).
- The PLOTSONA chart engine (C01-T03): a `chart` data source that recognises Office (XLSX, PPTX, DOCX), Vega, Vega-Lite, Plotly and Highcharts, HTML, SVG, PDF, PNG and JPEG files by their contents, not their names, and reads them under size, decompression, depth and work limits, so zip bombs, entity-expansion attacks and oversized files stop with a clear error. Each extraction comes with a report of the tier, the series and how many values are exact, calibrated or estimated. The extractors for each format follow in C01.
- Spec v0.2 (C01-T01, RFC-0004): a spec can name a `template` instead of writing its tracks, define `instruments` (SoundFonts), set `lint` rule levels and suppressions with reasons, give a chart source a typed `calibration` and `corrections`, and name `music.quantize` scales in words ("D minor pentatonic") or in cents. SONARITHM now writes `"specVersion": "0.2"`; v0.1 files keep working unchanged, with the same spec hashes, and `sonarithm spec migrate` updates them by changing only the version. The schema is `schemas/sonarithm-spec-0.2.schema.json`.
- Charts from Excel, PowerPoint and Word (C01-T05): a `chart` source reads the data behind an XLSX, PPTX or DOCX chart exactly (series names, categories or dates, and values) from the chart's own workbook when it has one, otherwise from the values the chart stores. Nothing outside the file is opened: external links and macros are ignored. A file with several charts reads the first and says so.
- Charts from Vega, Vega-Lite, Plotly and Highcharts (C01-T06): their JSON files, and local web pages that contain them, give their exact data. Nothing on a page runs and nothing is downloaded: data that lives at a web address or that only a script would produce is reported instead.
- Charts drawn as SVG (C01-T07): line, area, bar, scatter and pie charts exported as SVG by Vega-Lite, Plotly, D3 and similar tools give their values back through their axes, within 0.5 % on the test charts, marked as read from vector geometry. Series are named from the legend. A pie gives each slice's share in percent. Scripts and links in the file are never run or followed.
- Charts in vector PDFs (C01-T08): the same chart types read from PDF pages drawn as vector graphics (as Vega-Lite, Plotly and most plotting tools export them), within 0.5 % on the test charts. A PDF that holds only a picture of a chart says it needs the raster reader. Encrypted PDFs are not opened.
- Bundled fonts and the type scale (B02-T02): IBM Plex Sans and Mono at 400, 500 and 600 ship with the UI, unmodified and with IBM's OFL notice (`@sonarithm/ui/fonts.css`, `licenses.json`), so no font loads from the network. Type-scale, weight and numeric tokens; readouts get tabular figures with a slashed zero through the `snr-numeric` class, and Stylelint flags a readout without it. A font test page shows the figures for every weight.
- Design tokens (B02-T01): `@sonarithm/ui/tokens.css` with colour tokens generated in OKLCH for dark, light, high-contrast dark and high-contrast light themes, chosen from the theme setting or the OS (including its contrast preference), with forced-colours and reduced-motion handling and spacing, radius and motion tokens. Every text pair meets 4.5:1 and every border, focus, accent and signal pair 3:1 in every theme. Stylelint rejects hard-coded colours, spacing and durations, gradients, glow, blur, large radii and stray shadows.
- The earcon set (B03-T06): the designed earcons replace A05's placeholders; the app can play any earcon live (`Command::Earcon`); each has a text equivalent for the log and speech; a new gap earcon marks missing values when the spec asks for it.
- Context cues (B03-T05): AUDAXIS adds the tick track (short clicks at the major x ticks for discrete notes, SDR-16), the dynamic reference tone (the series maximum while values rise and the minimum while they fall, in its own timbre, SDR-17) and the spoken legend before playback (title, ranges, units, polarity, mode and cues, SDR-18). The render engine gains a `click` instrument.
- Announcements (B03-T03): AUDAXIS composes what the screen reader says for every cursor move, boundary, invalid action, where am I and pause from the shared message catalogue, terse or verbose, in the listener's part order. Unit names are spoken and symbols shown. Every estimated or derived value carries its qualifier. A queue keeps only the latest navigation announcement, never drops errors, and logs everything with a link to its data point.
- The navigation cursor (B03-T02): every movement verb of the keymap (step, jump by 10 %, first and last, in and out, lateral to another series, maximum and minimum, insights, landmarks, go to x, find value, Enter) and "where am I". Moves never wrap: at an edge the cursor stays and reports the boundary earcon; a verb that does not apply reports why.
- Stereo placement and the never-alone guard (B03-T11): AUDAXIS keeps every stereo position in range and warns when a data track varies only in pan, only in timbre, or in pitches outside 65–1480 Hz, so essential information survives mono output, NVDA's sound split and high-frequency hearing loss (A11Y-14). Binaural and multichannel requests play in stereo with a warning until D03.
- The navigation tree (B03-T01): the `sonarithm-audaxis` engine crate builds a NavTree (dataset, series, segments, points with their data rows, axes, insights and filters) from each compiled Score, and the compiler returns it beside the Score (`Compiled::nav`). The tree types live in `sonarithm_core::nav`.
- Message catalogues and locale formatting (B02-T08): the `sonarithm-i18n` crate with Fluent catalogues shared with the desktop UI, ICU4X number and date formatting that matches `Intl.NumberFormat`, spoken unit names (symbol, terse and verbose), and the `en-XA` pseudo-locale with a check for hard-coded, concatenated and truncated strings; the `@sonarithm/i18n` package and the `sonarithm/no-literal-ui-string` ESLint rule.

- Render engine (phase A05):
  - `sonarithm-dsp` oscillators: sine, triangle, and band-limited (PolyBLEP) saw and square, computed with IEEE 754 arithmetic only so renders stay bit-identical across platforms.
  - `sonarithm-dsp` envelopes: ADSR with raised-cosine onset and offset ramps of at least 5 ms, about 40 ms for notes (SDR-22); retriggers and releases never step.
  - `sonarithm-dsp` filters (one-pole low-pass; RBJ low-, high- and band-pass), a constant-power panner and a linear parameter smoother (10 ms).
  - `sonarithm-render` plan builder: a Score becomes a `RenderPlan` in frames, with resolved frequencies, gains, pan gains, instruments and voice-pool sizes; unknown instruments raise `SNR-RENDER-001` and fall back to the mallet preset.
  - `sonarithm-render` render graph: preallocated voice pools, data, context, earcon and monitoring buses, a sample-accurate scheduler and a transport (play, pause, stop, seek, loop, speed and live cues) with crossfades instead of cuts. Earcon sounds are provisional until B03.
  - `sonarithm-render` real-time channels: a wait-free command ring that coalesces on overflow, plan swaps with a crossfade whose old graph is freed off the audio thread, and an engine-state triple buffer for telemetry.
  - Offline rendering and audio export: `OfflineRender` plays a plan through the same render path in fixed blocks, and `sonarithm-export` writes 24-bit PCM or 32-bit float WAV and 24-bit FLAC.
  - Hearing safety on the master: a look-ahead true-peak limiter at −1 dBTP, and a start-up ramp from −20 dB over 500 ms whenever a playback stream opens.
  - ISO 226:2023 equal-loudness compensation, on by default when a plan is built (SDR-24), and an EBU R128 loudness and true-peak meter for exports.
  - Exports write a render manifest (`*.render.json`, with a generated JSON Schema) and a WebVTT cue sidecar (`*.cues.vtt`) next to the audio, and normalize loudness with one static gain.
  - `sonarithm-audio`: the `AudioBackend` trait, a cpal backend, a timer-driven null device for tests, and a `Player` that recovers from device loss at the same transport position, paused until the user resumes.
  - A Windows WASAPI backend (ADR-0016): RAW shared mode by default, so OEM enhancement processing no longer adds latency and gain after the limiter, with exclusive mode as an opt-in; a latency measurement tool and per-device latency calibration.
  - Render benchmarks (PB-03) on a reference benchmark Score; faster voices and limiter. The mallet preset's brightness now tilts its partials instead of filtering them.
  - A golden-audio harness (`cargo xtask golden`, six cases in `tests/golden/`) and CI jobs that render on Windows, Linux and macOS and compare the results (PB-06).

- ECHOMETRIC research instrumentation (phase A08):
  - `sonarithm-echometric` stimulus generators, each deterministic from its parameters and a seed, with the published parameters documented next to SONARITHM's: GEN-001 trend reversals × density (Nees & Walker 2008), GEN-002 price series with click and reference-tone columns (Smith & Walker 2005), GEN-003 SNR-controlled transit light curves (Tucker Brown et al. 2022) and GEN-004 correlation triplets (Elmquist et al. 2024). Every stimulus carries its ground truth, a canonical CSV with a SHA-256 digest, a provenance manifest and notes on where it departs from the published design.
  - `sonarithm-echometric` study runner library: TOML protocol files (`sonarithm-study/0`) with conditions, blocks and generator parameters, checked with `SNR-ENG-600`–`607` diagnostics; a seeded trial order with counterbalancing; responses scored against each stimulus's ground truth (point estimation, trend identification, counting, choice); a JSONL log (`sonarithm-study-log/0`) with pseudonymous codes and no paths; pause, and resumption from the log in a new run.
  - `sonarithm study check` and `sonarithm study run`: check a protocol and its condition specs, then run a session with one plain line per prompt and typed answers (screen-reader friendly), replays, pauses, breaks, `--resume`, the silent `--audio null` output, and audio context recorded only as entered; with the pilot protocol `examples/studies/pilot-001`. `sonarithm-echometric` is now published with the CLI.
  - Replication gallery (`replication/`): Smith & Walker's context-cue conditions, Nees & Walker's density × reversals cells, Tucker Brown et al.'s transit curves and the Erie gallery subset, rendered from committed specs with their records; `cargo xtask replication` regenerates the stimuli and checks every render on three operating systems, and `--timings` measures them.
- SONOTRACE streams (phase B06, Lane R):
  - `sonarithm-data` `StreamTable`: bounded, append-only storage for live data with row sequence numbers, a row or time-window capacity with a hard row limit, cheap snapshots that later appends never change, and `SNR-DATA-071` when rows are dropped before a reader read them; provenance columns kept in canonical form.
  - `sonarithm-sonotrace`, the SONOTRACE engine: the spec's `stream` source reads the window of a connected stream; live encoding emits each new row's events exactly once and replays deterministically; scrub grains preview a track's value at the cursor; long series play in windows.
  - `sonarithm-stream`: live stream adapters for WebSocket and OSC (default features), serial and MQTT (opt-in features) and file tail, each opened only with the user's explicit consent; messages become rows through a schema, fill a bounded stream table, and the connection reconnects, pauses and stops on request.
  - Monitoring soundscape (B06-T04): in `mode: "monitoring"` the Score gains a calm ambient bed that brightens on detected events instead of getting louder, a soft `E-STREAM` chime per event, and `E-ALARM` only for alarms the user configured with high salience. An experimental comfort report says how much of the session the bed is bright (SDR-39). The bed and its values are proposals until listeners evaluate them.
  - Stream notices and controls (B06-T05): at most one spoken notice per stream every 5 seconds, summing up the events since the last one, with stale events dropped and errors and alarms always spoken. The app core opens a stream only after the user approves an offer (`stream_offer`, then `stream_connect`), and every stream can be paused, resumed, hidden or stopped.
  - Live playback of a stream (B06-T07): `live_start` plays an open stream through a spec whose source is that stream. About once a second the newest window is compiled and swapped in while playing, so playback follows about 2 seconds behind the newest data and never stops at the end of a window; `live_stop` pauses. A window that does not compile is reported once, and playback goes on with the last one that did. The transport state also reports underruns. A stream soak (`stream_soak` example, nightly job) checks PB-11: a 1 kHz stream played live with bounded memory and no rows lost.
  - Profiles (B03-T08, ADR-0020): portable, schema-validated JSON profiles of listener preferences (pitch range, timbre, marks, pace, polarity and the one-key flip, context cues, verbosity, part order, modalities, speech, keymap), five presets (BLV chart reading, Analyst, Classroom, Presentation, Monitoring; proposals until co-design), a project profile saved in the bundle, import and export, and an effective-settings view naming where every value comes from. Sound preferences only fill what a spec leaves unset, and the compiled spec records them, so every render reproduces without the profile.
- Desktop app core (phase B01, Lane R):
  - `sonarithm-app`, the headless app core behind the desktop app: one `App::dispatch` entry point for the IPC protocol v1 ([ADR-0017](docs/decisions/0017-ipc-protocol-v1.md)) with datasets, the spec and its undo history, compile reports with diagnostics, the authoritative transport (play, pause, stop, seek, speed, loop, stop all audio) on its own control thread, export jobs with progress and cancellation, device selection, and versioned settings with migrations and crash-safe writes. Playback starts only on a play command (A11Y-15); a new Score, a device change or a device failure pauses it. `SNR-APP` diagnostic codes.
  - `cargo xtask network-deny`: the app-core tests run under strace (Linux), `sandbox-exec` (macOS) or Windows Filtering Platform auditing, and any outbound connection attempt fails the run; a self-test proves each mechanism catches a deliberate one (NFR-04).
  - Spec patches: `spec_apply` applies a JSON Patch (RFC 6902) to the session's spec as one undoable edit and returns the result's diagnostics; `spec_validate` checks spec text; undo and redo restore the spec byte for byte.
  - Project files: `.sonarithm` bundles ([RFC-0002](docs/rfcs/0002-project-format-v1.md)) save the specs and the datasets, embedded or linked by fingerprint, and reopen byte for byte; damaged, altered or unsafe bundles are refused, linked data that changed or is not a data file stays unavailable, and no absolute path is ever stored. Autosaves are offered for recovery after a crash. Commands `project_new`, `project_open`, `project_save`, `project_save_as`, `project_recent` and the recovery commands.
  - Speech sequenced with sonification: the cue plays before the announcement, only cues play while an arrow key repeats, speech waits during playback except errors and alarms, the current value is announced on pause, and a spoken response pauses playback (or ducks it 20 dB, as a setting). Optional self-voicing through the platform speech engine (`sonarithm-speech`, off by default) ducks sonification while it speaks. `announce_repeat` speaks the last announcement again. Export cue sidecars no longer overlap.
  - View tiles and table pages: `view_get` returns M4 tiles (pixel-exact at any zoom) or LTTB overviews of two fields, and `table_page` returns sorted pages of rows with their row indices, as binary views the UI reads without copying.
  - Typed IPC: `cargo xtask codegen` generates the protocol's TypeScript types with ts-rs into `@sonarithm/ipc`, with the command → reply table, the event → channel table and the binary view layout. `@sonarithm/ipc` adds the `IpcTransport` seam, `connect` (fails fast when UI and host speak different protocol versions), a mock transport for tests and a zero-copy binary view reader.

### Changed

- Offline rendering is about 1.5 times faster (#185): the benchmark Score now renders at 60 times real time on four efficiency cores (PB-03 met), with exactly the same output as before.

### Fixed

- `sonarithm-data`: `ReadOptions::without_inference()` keeps the field semantics declared in `fields` (type, unit, concept, role, label, description) instead of dropping them (#156).

### Security

- Hostile chart and Parquet files fail fast instead of crashing, exhausting memory or running for seconds (#374): a `Date.UTC` call with an enormous argument in an HTML chart page, SVG arcs with huge radii or far end points, and a Parquet page header with a mistyped field. Fuzzing found them before any release, so no published version is affected and no advisory is needed. Each input is a regression seed replayed on every test run.
